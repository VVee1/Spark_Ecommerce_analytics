#Spark E-commerce Analytics (电商订单数据分析)

##本项目基于PySpark实现电商订单全链路ETL开发，自主生成10万条仿真订单，完成数据清洗与多维度营收指标统计，落地结构化报表。

##项目结构
```text
spark-ecommerce-analytics/
├── scripts/
│   ├── generate_orders.py      # 模拟数据生成 
│   └── order_etl_analysis.py   # 核心分析 (商品种类/支付方式/销售额)
├── data/                       # 存放运行脚本生成的原始模拟数据 (data 文件夹初始为空，仅包含.gitkeep 文件以保留目录结构)
├── output/                     # 存放分析结果 (运行脚本后自动生成该文件夹及分析结果)
├── .gitignore                  # Git 版本控制忽略规则
├── requirements.txt            # 所需依赖包列表
└── README.md                   # 项目说明文档
```
##环境依赖
```text
Python 3.7+
Apache Spark 3.x
Java 8+
```
安装依赖：
```text
pip install -r requirements.txt
```

##快速运行
1.生成数据:
```text
python scripts/generate_orders.py    #会在 data/目录下生成 10 万条模拟订单的csv文件
```
2.执行分析:
```text
python scripts/order_etl_analysis.py   #分析结果会输出到 output/目录
```

##核心分析指标
本项目通过 PySpark 对电商订单数据进行深度挖掘，主要产出以下三个维度的业务洞察：
1. 商品品类营收排行
处理逻辑：过滤金额≤0 无效脏订单，按商品类目分组聚合，汇总全量销售额与有效下单量；
业务价值：定位头部热销品类与高营收类目，辅助运营制定活动投放、备货策略；
示例：
```text
| 商品类别 | 总销售额 | 订单量 |
| 零食 | 2,525,648.76 | 16,829 |
| 美妆 | 2,523,327.97 | 16,674 |
```
2. 用户支付渠道分布统计
处理逻辑：按 支付宝/微信/银行卡/货到付款 分组，统计各类渠道订单总量与占比；
业务价值：挖掘用户支付偏好，优化收银配置、洽谈支付渠道费率，降低平台手续费成本；
示例：
```text
| 支付方式 | 订单量 (单) |
| 支付宝   | 25,067 |
| 微信     | 24,989 |
| 银行卡   | 24,961 |
| 货到付款 | 24,983 |
```
3. 全周期每日营收时序报表
处理逻辑：提取订单日期字段，按自然日聚合单日营收，形成连续时间序列数据；
业务价值：监控每日营收波动，识别销售淡旺季、活动峰值，指导库存备货与排期；
示例：
```text
| 日期       | 总销售额 (元) |
| 2025-01-01 | 707,532.14 |
| 2025-01-02 | 815,699.32 |
```

##数据字典说明
| 字段名 | 字段含义 | 字段说明 |
|--------|----------|----------|
| order_id | 订单编号 | 全局唯一订单主键，ORD 开头编号 |
| user_id | 用户 ID | 下单用户唯一标识 |
| category | 商品品类 | 六大品类：零食/美妆/生鲜/家电/服饰/数码 |
| pay_type | 支付方式 | 支付宝、微信、银行卡、货到付款 4 种渠道 |
| order_amount | 订单实付金额 | 单笔订单金额ETL，过滤≤0 异常脏数据 |
| order_status | 订单状态 | 已完成、待付款、已取消、退款成功 |
| create_time | 下单时间 | 订单创建年月日时分，统一格式化日期 |

##注意事项
1.**Spark 环境变量**：确保系统已配置 `SPARK_HOME` 和 `JAVA_HOME` 环境变量。

2.**路径问题**：脚本使用相对路径读取 `data/` 目录，请务必在项目根目录下执行命令，而非进入 scripts 目录执行。

3.**如何查看output中的分析结果**：由于 Spark 采用分布式并行计算机制，默认情况下会将输出结果切分为多个分区文件（即 part-00000、part-00001... 格式），而不是生成单个 CSV 文件。这是正常现象，并非报错。
 output目录结构说明：
 ```text
 output/
 ├── category_sales/     # 商品品类营收排行结果
 ├── payment_stats/      # 支付方式订单统计结果
 └── daily_revenue/      # 每日营收趋势结果
```
 每个文件夹内包含若干 part-xxxxx.csv 文件和一个 _SUCCESS 标记文件。
 
 如何进行查看？
 方式 A：使用命令行合并（推荐）
 如果你熟悉终端命令，可以直接将所有分片合并为一个完整的 CSV 文件：
 ```text
 cat output/category_sales/part-*.csv > category_sales.csv         #以查看“品类排行”为例
 ``` 
 
 方式 B：直接打开任意分片
 如果数据量较小（如本项目的 10 万条模拟数据），你可以直接用 Excel 或文本编辑器打开任意一个 part-00000-....csv 文件查看内容。虽然数据被分散了，但表头和内容格式是完整的。
 （提示： _SUCCESS 文件是一个空文件，它的存在代表该任务已成功完成。如果文件夹里没有这个文件，说明任务可能中途失败。）
